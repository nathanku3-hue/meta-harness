## Phase 2 — Git autopilot

### Functional slice

WORK preserves a dirty user checkout and completes the slice in a clean isolated worktree without requiring manual Git preparation.

### Deliver

- root/default-branch/upstream/HEAD/dirty/worktree discovery;
- intended-base selection from product authority and Git facts;
- clean isolated worktree creation;
- deterministic slice branch naming;
- focused commit creation;
- configured exact branch push;
- notification before external or irreversible actions.

### Hard prohibitions

- no auto-stash;
- no reset or clean;
- no overwrite of existing user work;
- no force push;
- no shared-history rewrite;
- no assumption that the default branch is `main`;
- no blanket installation into dirty checkouts, archives, evidence directories, or managed worktrees.

### Validate

- source dirty checkout remains byte-identical;
- isolated worktree starts clean at exact base;
- branch, commit, and push are deterministic;
- integration readiness is reported without contaminating other repositories.

## Phase 4 — Decision-bound research

### Functional slice

One external research question changes one real product or implementation decision.

### Deliver

- conditional RESEARCH skill;
- decision question and stop condition;
- primary-source rejection-first candidate matrix;
- COPY/MODIFY/REJECT decision record;

### Validate

## Phase 5 — Event-triggered retrospective

### Functional slice

The system learns from one expensive or surprising slice without adding a mandatory round to ordinary work.

### Deliver

- conditional RETROSPECT skill;
- closure, abandonment, budget, repeated-failure, model-change, and explicit-request triggers;
- KEEP/DELETE/SIMPLIFY/TEST/INVESTIGATE output;
- non-authoritative improvement-candidate record;
- generated handover separate from reflection.

### Validate

- normal successful slice produces no retrospective;
- retrospective cannot reopen product work;
- findings require repeated failure or material irreversible risk before implementation.

## Phase 6 — Harness diet

### Functional slice

Historical scenarios pass with fewer active instructions, reports, phases, and commands.

### Deliver

- adaptive engineering-reasoning skill;
- concise communication-style fingerprint;
- consolidation of overlapping routers and contracts;
- removal or demotion of phase choreography, context scoring, expert packets, detailed worker reports, and automatic next-action generation;
- no backward compatibility for retired process concepts without active consumers.

### Validate

- same or better decision accuracy;
- lower time to first Product Episode;
- fewer human interruptions;
- smaller always-on context;
- fewer permanent surfaces;
- no increase in escaped defects or unsafe irreversible actions.

## Phase 7 — Constraint challenge

### Functional slice

A major model upgrade causes obsolete scaffolding to be identified and deleted safely.

### Method

Run holdout scenarios with:

1. model plus repository only;
2. lean role skills plus charter;
3. full old harness.

### Disposition

- model+repo passes: delete the rule;
- model+repo fails and lean skills pass: keep the smallest skill;
- lean skills fail and a deterministic check passes: retain the smallest test or hook;
- sandbox or external control remains only for real blast radius.

Each retained non-security constraint records origin, regression, last demonstrated value, and deletion condition.

## Global execution law

- Product Episode first.
- One repair maximum before method re-evaluation.
- Reversible work automated and reported.
- Existing user work preserved.
- External or irreversible action announced before execution.
- No automatic successor after closure.
- No product progress claim from process artifacts alone.
