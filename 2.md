# What does “maximum” parallelism mean?

There is one subtle distinction I would make explicit in the design.

**Maximal parallelism** means:

> Keep allocating until no additional compatible candidate exists.

**Maximum parallelism** means:

> Choose the globally largest compatible set.

Those are not always the same.

Example:

```text
A conflicts with B and C
B does not conflict with C
```

Greedy:

```text
choose A
→ parallelism = 1
```

Maximum:

```text
choose B + C
→ parallelism = 2
```

I would design the protocol so it *can* support maximum packing, but initially make the kernel merely validate compatibility.

Repository intelligence can compute:

```text
ParallelPack = {
    Dashboard,
    Cascade,
    Scrapers
}
```

The kernel proves:

```text
all eligible
all unclaimed
pairwise non-conflicting
```

No OR-Tools required.

For the small number of product lanes you're likely to have, even an exact deterministic search of the conflict graph would be tiny if you eventually want literal maximum cardinality.

But **do not put “high EV” judgment in the kernel**. The plan is right about that separation.

# Extra point 1: does this solve the “gate first worker” mental model?

**Not completely yet.**

Your plan has the execution gates:

```text

→ claim
→ execution
→ SAW
→ commit
```

But it needs a gate *before* `BLOCKED / OWNER_DECISION`:

```text
FORWARD-MOTION GATE
```

The fundamental worker/planner reasoning should be:

```text
DESIRED STATE
    ↓
What fact/capability is actually required?
    ↓
What constraints are truly hard?
    ↓
What interchangeable means can satisfy it?
    ↓
Can any available means move us forward?
    ├─ YES → use best viable means
    └─ NO
        ↓

        ├─ NO → replan
        └─ YES → owner
```

In other words:

> **A failed implementation route is not a blocked outcome.**

That is the first-principles correction.

The agent shouldn't reason:

```text

→ expected librarian/API unavailable
→ BLOCKED
```

It should reason:

```text
Need holdings data sufficient for outcome X
        ↓
What properties are actually required?
- issuer
- holder

- history

        ↓

        ↓

        ↓
```

**1. Understand — WHAT must become true?**


**2. Devise — WHAT interchangeable means can produce it?**


> **Outcomes are stable; means are disposable.**

That applies not only to data sources, but libraries, models, runtimes, frameworks and internal architecture.
